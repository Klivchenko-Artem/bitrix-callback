# Обратный звонок для 1С-Битрикс

Модуль `artem.callback` и компонент `artem:callback.form`: форма заказа звонка,
заявки в собственной таблице, письмо менеджеру, ограничение частоты отправки.

Написан как показательный проект под Bitrix Framework: с установщиком, страницей
настроек, списком в админке и тестами на бизнес-логику.

## Что внутри

### Модуль (`local/modules/artem.callback`)

- установка и удаление: своя таблица через D7 ORM, почтовое событие с шаблоном,
  копирование компонента в `/local/components`, демо-страница `/callback/`;
- при удалении спрашивает, оставить ли заявки в базе;
- страница настроек (`options.php`): получатели письма, лимит заявок с адреса,
  интервалы для звонка, обязательность комментария и согласия;
- надписи интерфейса вынесены в `lang/ru` в модуле, компоненте и шаблоне. Тексты шагов установки,
  тело письма и сообщения об ошибках компонента пока живут в коде, их вынос имеет смысл,
  когда появится вторая локализация;
- раздел в админке со списком заявок: фильтр по телефону, имени и статусу,
  сортировка, групповые действия (обработана / спам / вернуть в новые / удалить);
- права на модуль выданы через `MODULE_GROUP_RIGHTS`.

### Компонент (`artem:callback.form`)

- отправка через ajax-действие компонента (`Controllerable`), а не через
  самописный обработчик: подпись параметров и проверка сессии достаются от ядра;
- параметры шаблона: заголовок, надпись на кнопке, текст успеха, показывать ли
  комментарий и выбор времени, ссылка на политику, слать ли письмо;
- шаблон без библиотек: обычный `<form>`, ошибки подставляются в поля по коду;
- лимит заявок считается по таблице заявок с адреса посетителя за период и
  проверяется под блокировкой в базе, чтобы пачка одновременных запросов не
  проскочила. Адрес берётся из `REMOTE_ADDR`: заголовок `X-Forwarded-For` шлёт сам
  клиент, и доверять ему нельзя. За прокси настоящий адрес должен подставить
  веб-сервер (`real_ip` в nginx). Если сайт открыт через прокси, а настоящий адрес
  не подставлен, страница настроек модуля об этом предупреждает;
- ошибки сохранения и отправки письма пишутся в журнал событий Битрикса.

### Логика, которая не знает про Битрикс (`local/modules/artem.callback/lib`)

| Класс | Зачем |
| --- | --- |
| `Service\PhoneNormalizer` | приводит номер к `+7XXXXXXXXXX`, отсекает не-телефоны |
| `Service\RequestValidator` | проверяет поля формы по настройкам модуля |
| `Service\RateLimiter` | не даёт слать заявки пачками с одного адреса |
| `Service\PageUrlSanitizer` | обрезает адрес страницы и отбрасывает всё, кроме http и https |
| `Bitrix\DbRateStorage` | счётчик для лимита по таблице заявок, окно скользящее |
| `Bitrix\RequestRepository` | запись заявки, поиск свежего дубля, смена статуса |
| `Bitrix\Notifier` | письмо через почтовое событие |

Разделение сделано ради тестов: `Service\*` не тянут ядро и гоняются обычным
PHPUnit, адаптеры в `Bitrix\*` подставляются на сайте.

## Запуск

```bash
docker compose up -d
```

Поднимаются nginx, PHP 8.2-FPM, MySQL 8 и Mailpit. При первом старте контейнер
сам скачивает пробный дистрибутив «1С-Битрикс: Управление сайтом» (~300 МБ),
ядро в репозитории не лежит. Отдача 1С-Битрикса рвёт соединение, поэтому качается
циклом с докачкой; прогресс видно в `docker compose logs -f php`.

Дальше:

1. http://localhost:8081/, мастер установки Битрикса. Порт можно подвинуть:
   `PUBLIC_PORT=8090 docker compose up -d`.
   База: хост `mysql`, имя `bitrix`, пользователь `bitrix`, пароль `bitrix`.
2. В «Marketplace / Установленные решения» установить «Обратный звонок».
3. В «Настройки / Настройки продукта / Настройки модулей / Обратный звонок»
   вписать почту менеджера.
4. http://localhost:8081/callback/, демо-страница с формой.
5. http://localhost:8027/, Mailpit, там видно отправленные письма.
   Наружу почта не уходит.

Заявки: «Сервисы / Обратный звонок / Заявки».

## Тесты

```bash
composer install
composer test
```

35 тестов на PHPUnit 11: нормализация телефонов, правила валидации формы
(границы длины считаются в символах, а не в байтах), ограничитель частоты
со сдвигом времени в тестовом хранилище, границы настроек и приведение адреса
страницы к безопасному виду.
CI гоняет их же плюс `php -l` по всем файлам модуля.

## Чего здесь намеренно нет

- Инфоблока под заявки. Заявка не контент: ей не нужны разделы, свойства
  и права на элемент, зато нужен быстрый список с фильтром. Поэтому своя таблица
  на ORM, а не «инфоблок под всё».
- Капчи. На демо-стенде она мешает смотреть, а от ботов на этом уровне
  хватает лимита по IP; на живом сайте сюда встаёт reCAPTCHA или Битриксовый `captcha`.
- Реального SMTP. Пароли от почты в репозитории хранить нельзя, поэтому
  письма ловит Mailpit.
- Языковых файлов у классов из `Service\*`. Тексты ошибок валидации лежат
  прямо в коде: эти классы намеренно не знают про ядро, иначе их не получится
  гонять обычным PHPUnit. Всё, что видит администратор и посетитель через
  шаблон, локализовано как положено.

## Что проверено руками

Стенд поднят, Битрикс 26.150 установлен, модуль прошёл полный круг:

- установка: таблица, почтовое событие с шаблоном, компонент в `/local/components`,
  демо-страница, пункт меню в админке;
- удаление с галкой «сохранить заявки» и без неё: настройки, почтовое событие,
  счётчики и скопированные файлы уходят всегда, таблица только без галки.
  Галка обещает сохранить заявки, а не конфигурацию: с оставшимися настройками
  повторная установка подхватывала старые значения;
- повторная установка на чистое место;
- отправка формы: нормализация телефона (`8 918 000-11-22` в `+79180001122`),
  ошибки по полям, лимит по IP, письмо менеджеру в Mailpit;
- админка: фильтр по телефону и статусу, групповые действия, смена статуса.
